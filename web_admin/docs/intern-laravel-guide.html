4. How the code works

A. Blade sends the form

<form method="POST" action="{{ route('login.submit') }}">
    @csrf
    <input type="email" name="email">
    <input type="password" name="password">
    <button type="submit">Login</button>
</form>

name="email" becomes $request->email. The CSRF token protects the form from unauthorized submissions.

B. The route selects the controller

Route::post('/login', [LoginController::class, 'login'])
    ->name('login.submit');

C. The controller checks the request

// Validate browser input.
$data = $request->validate([
    'email' => ['required', 'email'],
    'password' => ['required', 'string'],
]);

// Retrieve the matching record from the existing table.
$user = User::where('EMAIL', $data['email'])->first();

// Compare plain input with the encrypted database password.
$passwordIsCorrect = Hash::check(
    $data['password'],
    $user->PASSWORD_HASH
);

D. Laravel returns a result

// Success
return redirect()->route('admin.dashboard');

// Failure
return back()
    ->withErrors(['email' => 'Invalid email or password.'])
    ->onlyInput('email');

The email is kept after an error for convenience. The password is deliberately not kept.

7. Suggested intern lesson

  1. Open the Blade login page and identify the form fields.
  2. Submit it and inspect the browser Network tab.
  3. Find POST /login in routes/web.php.
  4. Temporarily use dd($request->all()) to see the submitted data, then remove it.
  5. Walk through LoginController::login().
  6. Open User.php and explain table and column mapping.
  7. Demonstrate both successful and failed login.
  8. Explain sessions and middleware.
  9. Repeat the pattern with one admin listing page.
  10. Introduce the mobile API only after the web flow is understood.
